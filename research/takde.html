Research/TAKDE

Real-time · sparse · drifting data

Learning a distribution that will not sit still.

When each snapshot has only a few brand-new samples and the distribution keeps moving, how much of the past should you remember?

Yinsong Wang · Yu Ding · Shahin ShahrampourIEEE TPAMI · 2023

Project 04

A strange kind of data

Picture a nanoparticle synthesis reactor. Inside the chamber, billions of particles nucleate and grow, and their size distribution determines the quality of the final product. To monitor the process, we periodically pull out a tiny sample and image it under a microscope.

That gives us data with three awkward properties at once. Each snapshot contains only a handful of particles. The particles are brand new every time, so we cannot track any individual particle across snapshots. And the underlying distribution keeps moving as the particles grow. What we want is the full size distribution right now, updated in real time.

What people usually do

One classical route is filtering: assume the distribution has a parametric form, say a Gaussian, and track its parameters with a linear (Kalman-type) filter. That is fast, but real particle-size distributions are often skewed or multimodal, and a wrong shape assumption cannot be fixed by more data.

The nonparametric route is the kernel density estimator (KDE): put a small bump on every observation and add them up. KDE is simple, flexible, and extremely fast. The trouble is that a single frame has so few points that its KDE is very noisy, so the variance is far too high. The obvious fix is to pool older frames, but pool too much and the estimate describes where the process was, not where it is.

Our idea: let the bias–variance trade-off decide

So the real question is: how should we pool older data? How many past frames should we use, and how much should each one count? We treated this as a bias–variance trade-off. Every older frame adds samples and lowers variance, but it also adds bias, because the distribution has drifted since that frame was taken.

We derived an upper bound on the asymptotic mean integrated squared error (AMISE) of a sliding-window KDE that makes this trade-off explicit: it shows how the error depends on the number of samples, the bandwidth, and how much the distribution changes between frames. Minimizing that bound tells us how long the window should be and how to weight each frame inside it. The result is TAKDE, the Temporal Adaptive Kernel Density Estimator, which is optimal in the worst-case AMISE sense instead of relying on a hand-tuned window.

The estimator adapts its memory to the pace of change.

What we found

Because TAKDE is still a kernel density estimator underneath, it keeps KDE's speed: each update only reweights a short window of recent frames. On synthetic and real-world data streams, it achieved higher test log-likelihood than state-of-the-art dynamic density estimators, including non-kernel methods, while using less runtime.
